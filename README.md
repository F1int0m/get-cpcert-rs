# get-cpcert-rs

[![CI](https://github.com/metron8/get-cpcert-rs/actions/workflows/ci.yml/badge.svg)](https://github.com/metron8/get-cpcert-rs/actions/workflows/ci.yml)
[![License: GPL v2](https://img.shields.io/badge/License-GPL_v2-blue.svg)](LICENSE)
[![MSRV](https://img.shields.io/badge/MSRV-1.75-blue)](https://www.rust-lang.org)

Утилита на Rust, извлекающая сертификат и закрытый ключ из контейнера КриптоПро 4/5 (форматы ГОСТ Р 34.10-2001, ГОСТ Р 34.10-2012/256, ГОСТ Р 34.10-2012/512) и сохраняющая их в PEM-файл, совместимый с OpenSSL 1.1.1+ с подключенным gost-engine.

Это переписанная на Rust версия [kov-serg/get-cpcert](https://github.com/kov-serg/get-cpcert) (GPL-2.0). Лицензия наследуется. Реализация полностью независимая — повторён только протокол (формат контейнера и криптопримитивы), исходный код написан с нуля на Rust.

## Использование

```bash
# Пароль через stdin (рекомендуется):
get-cpcert /path/to/MyKey.000 > cert.pem

# Пароль из файла:
get-cpcert /path/to/MyKey.000 --password-file ./pwd.txt > cert.pem

# Пароль аргументом (видно в `ps`, используйте только для скриптов в защищённой среде):
get-cpcert /path/to/MyKey.000 -p hunter2 > cert.pem

# Сразу в файл:
get-cpcert /path/to/MyKey.000 -o cert.pem
```

Контейнер — это директория (обычно `что-то.000/`), содержащая файлы `header.key`, `primary.key` (или `primary2.key`), `masks.key` (или `masks2.key`), `name.key`, `kek.opq`. Утилите нужны первые три. Если основных `primary.key`/`masks.key` нет, автоматически подхватываются варианты с суффиксом `2` (бывает в более новых версиях КриптоПро).

## Сборка

```bash
cargo build --release -p get-cpcert
# бинарник: target/release/get-cpcert
```

Минимальная версия Rust: 1.75. Чистые Rust-зависимости, без C-библиотек, без линковки против OpenSSL.

## Что поддерживается

- Алгоритм по OID из `header.key`:
  - `1.2.643.2.2.30.1` → ГОСТ Р 34.10-2001
  - `1.2.643.7.1.1.2.2` → ГОСТ Р 34.10-2012 (256 бит)
  - `1.2.643.7.1.1.2.3` → ГОСТ Р 34.10-2012 (512 бит)
- Кривые: CryptoPro_XchA_ParamSet (для 2001/2012-256), tc26_512_paramSetA (для 2012-512).
- Контейнеры, защищённые паролем, и контейнеры без пароля (KDF использует 2 итерации вместо 2000).

## Архитектура

| Модуль | Что делает |
| --- | --- |
| `asn1` | Минимальный BER/DER парсер (поддерживает indefinite-length). |
| `container` | Чтение `header.key`, `primary.key`, `masks.key`, извлечение полей. |
| `kdf` | KDF КриптоПро (варианты ГОСТ-2001 на Gost94 и ГОСТ-2012 на Streebog-256). |
| `gost28147` | Блочный шифр ГОСТ 28147-89 с переключаемыми S-боксами (CryptoPro A и TC26 Z). |
| `gost_ec` | Кривые ГОСТ Р 34.10, точки, скалярное умножение через `num-bigint-dig`. |
| `pem_out` | Шаблоны PKCS#8 PrivateKeyInfo и сборка финального PEM. |
| `lib.rs::extract` | Точка входа: оркестрация всего пайплайна. |
| `main.rs` | CLI. |

## Алгоритм

1. Распарсить `header.key` → определить OID алгоритма, получить 8 байт публичного ключа (`pub8`) и сам сертификат.
2. Из `primary.key` достать зашифрованный закрытый ключ.
3. Из `masks.key` достать маску и 12-байтную соль.
4. Вывести симметричный ключ KDF КриптоПро (`H((current⊕0x36)||salt_pass||(current⊕0x5C)||salt_pass)` с константой `"DENEFH028.760246785.IUEFHWUIO.EF"`).
5. Расшифровать `primary.key` ГОСТ 28147-89 (ECB), развернуть в big-endian → `key_with_mask`.
6. Снять маску: `raw_secret = key_with_mask · mask⁻¹ (mod q)`.
7. Проверить: `Q = raw_secret · G`, первые 8 байт `Q.x` в little-endian должны совпасть с `pub8` — иначе пароль неверный.
8. Вставить `raw_secret` в PKCS#8 шаблон, сформировать PEM-бандл.

## Замечания о безопасности

- Все секреты (ключ из пароля, расшифрованный закрытый ключ) затираются `zeroize` после использования.
- EC-арифметика в `gost_ec` **не constant-time**. Этого достаточно для оффлайн-извлечения собственного ключа, но не используйте этот модуль для рантайм-подписи в продакшене.
- Эту утилиту имеет смысл запускать только над *своим* контейнером. Извлечение закрытого ключа из чужого носителя без разрешения владельца — нарушение закона.

## Тестирование

```bash
cargo test --release
```

Прогоняется 31 тест по четырём пластам:

1. **Криптопримитивы** (хеши, шифр, EC): известные тестовые векторы (Streebog-256 из RFC 6986, ГОСТ Р 34.11-94/CryptoPro), round-trip ГОСТ 28147-89 на обоих наборах S-boxes, корректность параметров кривых (`q·G = ∞`, базовая точка на кривой), ассоциативность сложения, дистрибутивность скалярного умножения.

2. **Парсер ASN.1**: примитивные/составные теги, длинные формы длины, indefinite-length, OID-декодирование, реакция на обрезанные данные.

3. **Синтетический полный пайплайн** (`tests/synthetic.rs`): прогоняет всё от начала до конца на самим собой сконструированном контейнере GOST-2012-256 с известным приватным ключом. Подтверждает, что компоненты склеены правильно (расшифровали зашифрованное → сняли свою же маску → проверили свой же публичник → упаковали обратно → получили ровно тот ключ, что положили). Тест на неверный пароль проверяет, что мы аккуратно завершаемся с `InvalidPassword` вместо выдачи мусора.

4. **Интеграция против эталонных контейнеров** (`tests/integration.rs`): тест-харнесс ищет образцы в `tests/samples/<name>/{header.key, primary.key, masks.key, password, expected.pem}` и сравнивает наш PEM-вывод с эталонным побайтово. В репозиторий уже уложены все четыре эталонных сэмпла из `get-cpcert-bin.tar.gz`:

   ```
   [g2001]            OK (1389 bytes)   GOST R 34.10-2001
   [g2012256]         OK (1397 bytes)   GOST R 34.10-2012/256
   [g2012256_padded]  OK (1397 bytes)   тот же контейнер, файлы дополнены 0xFF
   [g2012512]         OK (1522 bytes)   GOST R 34.10-2012/512
   ```

   Все четыре дают **байт-в-байт идентичный** PEM по сравнению с эталоном оригинальной C-утилиты — это валидирует корректность реализации KDF, GOST 28147-89, EC-арифметики и PKCS#8-обёртки.
